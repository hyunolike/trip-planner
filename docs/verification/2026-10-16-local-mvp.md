독립 검토가 찾은 문제:

1. 이전 탭의 큐 스냅샷이 다른 탭의 저장된 초안을 덮어쓰던 문제. 저장 직전 이전에 확인한 직렬화 값과 비교하고, 달라졌으면 저장을 중지해 외부 저장 내용과 현재 입력을 보존한다.
2. 오래된 편집 초안이 새 서버 버전으로 다시 저장되던 문제. 초안에 기준 버전을 저장하고, 다르면 입력은 보여 주되 자동 저장/제출을 막는다. 명시적으로 서버 내용을 선택한 뒤 다시 편집한다. 확인된 자동 저장 초안은 제거한다.

## 검증 한계와 배포 준비

- 운영 배포·푸시·PR 수정·머지를 하지 않았다. GitHub 원격 CI는 재실행하지 않았으며 로컬에서 같은 사용자 흐름을 검증했다.
- Google 실제 계정 로그인, 실제 SMTP, Vercel→API의 운영 프록시 체인, 유료 호스팅·운영 관측성은 설정하거나 검증하지 않았다.
- 배포 전에 실제 URL, OAuth 리다이렉트, SMTP, DB/Valkey, 신뢰할 프록시 CIDR과 전달 헤더 정리 정책을 운영 환경에 맞춰 설정해야 한다. 실제 브라우저 IP별 요청 제한 검증이 필요하다.
- 공유 링크는 서버에서 회수된다. 이미 열린 화면이나 복사한 데이터까지 원격으로 지우지는 않는다.
- 오프라인 최초 접속/서비스워커/PWA와 공동 편집은 범위 밖이다. 큐는 탭 사이의 원자적 잠금이나 자동 병합을 제공하지 않는다. 외부 변경을 발견하면 덮어쓰지 않고 멈춘다.
- 기존 스트리밍 not-found 화면은 일부 경우 HTTP200과 noindex로 반환된다. 운영 SEO 검증에서 상태 코드를 다시 확인해야 한다.
- 준비물 체크는 서버화하지 않았다. 방문한 일정 완료만 서버에 저장한다.
- 브라우저 저장 공간이 막힌 경우 입력은 메모리에 남지만 탭 종료 후 복구를 보장하지 않는다. 화면에서 저장 실패를 표시한다.
- 새 의존성이나 자격증명을 추가하지 않았다. 기존 사이트와 샘플 데이터, 잠금 파일을 보존했다.
