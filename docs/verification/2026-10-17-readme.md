## 사용한 스킬

`skill-creator` 지침으로 만든 [evidence-readme](../../.agents/skills/evidence-readme/SKILL.md)를
작성 전에 읽고 그 증거 수집 → 구성도 검토 → 언어/링크 검증 절차를 사용했다.

- Codex 프로젝트 경로: `.agents/skills/evidence-readme/SKILL.md`, 호출 `$evidence-readme`.
- Claude Code 프로젝트 경로: `.claude/skills/evidence-readme/SKILL.md`, 호출 `/evidence-readme`.
- Claude 디렉터리는 정본으로 가는 상대 symlink다. 두 경로가 같은 파일로 해석되는 것을 확인했다.
- 기존 파일이 없음을 확인한 뒤 생성했다. 홈 설정·개인 스킬·플러그인 권한·자격증명을 변경하지 않았다.
- `skill-creator/scripts/quick_validate.py` 결과 `Skill is valid!`. 정적 검증이며 새 모델 실행은 하지 않았다.
- 이 저장소 범위의 스킬이다. 새 checkout/session에서 발견하며, 다른 저장소에서는 정본 폴더와
  Claude symlink를 복사하되 기존 동일 이름 스킬을 먼저 확인한다. 전역 설치로 주장하지 않는다.

## 구성도와 검증

[원본 생성기](../../scripts/docs/render_architecture.py)는 Python 표준 라이브러리만 사용한다.
저장소 루트에서 `python3 scripts/docs/render_architecture.py`로 한·영 SVG 네 개를 다시 만든다.
SVG는 외부 폰트/스크립트/이미지를 요청하지 않으며 title/desc를 포함한다. README는 상대 경로와 alt를 사용한다.

`rsvg-convert`로 네 SVG를 PNG로 렌더링하고 화면으로 문자 잘림·겹침·화살표 방향과 범례를 검토했다.
브라우저→지도 타일 경로를 API 외부 호출과 분리했고, 현재 Preview와 미배포 제안을 별도 영역으로 표시했다.
재생성 결과가 동일한지도 확인한다. SVG 원본과 생성기는 Git에 보관하고 QA PNG는 임시 파일로 둔다.

README/스킬의 상대 파일 링크·SVG XML·언어 상호 링크·스크립트 명령의 존재를 검사하고
`git diff --check`를 수행했다. 실제 운영 연결이나 권한 없는 서비스 가입/배포는 검증 때문에 실행하지 않는다.
API 전체166 테스트와 관련 새14 테스트는 [추가 검증](2026-10-17-free-hosting.md)에 기록했다.

추가로 GitHub의 `53e03cb` 파일 Preview에서 한국어 문서의 실제 시스템/배포 이미지와 영어 진입 링크를
확인했다. 두 문서 모두 GitHub의 Markdown 표·코드 블록과 이미지 경로가 정상 표시된다.
첫 CI의 기존 지도 테스트에서 mock 복원과 React cleanup 순서 문제가 드러나, 전역 mock을
제거하기 전에 명시적으로 unmount하도록 고쳤다. 웹 전체42파일/211테스트 및 해당 파일 Biome 검사 통과.
최종 커밋의 CI 결과는 PR의 exact HEAD 검사로 확인한다.
