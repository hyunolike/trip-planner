# 0003. 쓰기는 JPA, 읽기는 jOOQ, QueryDSL은 쓰지 않음

- 상태: 제안
- 날짜: 2026-10-16

## 맥락

쓰기는 단순하다. 여행, 날짜, 스톱을 만들고 고치고 순서를 바꾼다. 읽기는 복잡하다. 일정표 한 장을 그리려면 여행, 날짜, 스톱, 장소, 가이드, 링크, 체크리스트, 사용자별 완료 상태를 한 번에 가져와야 하고, 내 여행 목록에는 멤버와 진행률 집계가 붙는다.

한국 Spring 생태계에서 동적 쿼리는 흔히 QueryDSL로 쓴다. 그런데 원본 QueryDSL은 2021년 7월 이후 릴리스가 없고, Spring Data 공식 문서는 커뮤니티 포크(OpenFeign)를 "best-effort"로만 지원한다고 적는다. 포크의 유지보수자는 사실상 한 명이다.

## 결정

- 쓰기 모델은 Spring Data JPA(Hibernate 7)로 다룬다. 엔티티는 aggregate 단위로 두고, 컨트롤러에는 DTO와 커맨드만 노출한다.
- 읽기 모델은 jOOQ 3.21로 쓴다. 일정표 전체 트리, 목록 집계, 진행률처럼 조인과 집계가 많은 쿼리를 SQL에 가깝게 쓰고 타입 검사를 받는다. PostgreSQL은 jOOQ 오픈소스 에디션 범위라 비용이 없다.
- jOOQ 코드는 Flyway 마이그레이션 결과 스키마에서 생성한다. Testcontainers로 PostgreSQL을 띄워 생성한다.

## 고려한 대안

| 대안 | 기각 이유 |
| --- | --- |
| QueryDSL(OpenFeign 포크) | 유지보수가 불확실하다. Boot 4와 Hibernate 7 호환이 늦게 따라올 위험이 있다. |
| JPA만 사용(JPQL, Specification) | 일정표 트리 조회에서 N+1과 fetch join 제약을 피하기 어렵다. 집계 쿼리가 문자열 JPQL로 흩어진다. |
| Kotlin JDSL | JPQL을 타입 안전하게 쓰는 도구라 JPA 조회의 한계는 그대로다. |
| Exposed | 쓰기까지 Exposed로 가면 Spring Data와 트랜잭션 관리 방식이 갈린다. |

## 결과

- 좋은 점: 쓰기는 도메인 규칙을 엔티티에 두고, 읽기는 필요한 컬럼만 정확히 가져온다. 면접에서 "왜 QueryDSL을 안 썼나"에 출처를 대고 답할 수 있다.
- 감수할 점: 두 도구를 익혀야 한다. jOOQ 코드 생성 단계가 빌드에 추가된다.

## 다시 볼 조건

- jOOQ 읽기 쿼리가 다섯 개 이하로 남으면 JPA 하나로 합치는 것을 검토한다.
