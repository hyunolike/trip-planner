# 0007. 지도 엔진 MapLibre와 Protomaps

- 상태: 제안
- 날짜: 2026-10-16

## 맥락

기존 앱은 Leaflet과 OpenStreetMap 타일로 하루 동선을 그리고 경로를 재생한다. 사용자는 한국인이고 첫 목적지는 일본이다. 지명이 한국어로 보이면 좋다. 지도 호출량은 사용자 수에 비례해 늘어나므로 비용 구조가 중요하다.

조사 결과 카카오맵 API는 공식적으로 국내 지도만 제공한다. 2026-07-21부터는 개발자 계정의 첫 번째 앱에만 무료 쿼터를 준다. 네이버 지도는 해외 지원 여부를 공식 문서로 확인하지 못했다. Google Maps는 2025-03부터 월 1만 회 무료 후 동적 지도 1,000회당 $7이다. Leaflet은 2023-05 이후 npm 릴리스가 없다.

## 결정

- 지도 렌더링은 MapLibre GL JS 6와 `react-map-gl/maplibre`로 한다.
- 타일은 Protomaps 베이스맵을 PMTiles 파일로 만들어 Cloudflare R2에서 서빙한다. 범위는 일본과 한국이고, 라벨은 `name:ko`를 우선한다. 개발 초기에는 OpenFreeMap으로 시작해도 된다.
- 장소 검색과 이동 시간은 Google Places와 Routes를 서버에서만 호출하고 결과를 캐시한다. 브라우저에 Google 키를 두지 않는다.
- 국가별 지도 공급자 어댑터 인터페이스를 둔다. 국내 여행을 지원할 때 카카오 Local API를 붙인다.
- 일정 순서 변경은 `@dnd-kit/core` 6.3과 sortable로 한다. 모바일은 길게 눌러 끌기(`activationConstraint: { delay, tolerance }`)다. 순서 값은 fractional index 문자열로 저장하고, 스톱의 `version` 컬럼으로 동시 수정을 감지한다.

## 고려한 대안

| 대안 | 기각 이유 |
| --- | --- |
| Leaflet 유지 | 유지보수가 멈췄고 벡터 타일과 지도 회전, 부드러운 카메라 이동이 약하다. 경로 재생 연출이 MapLibre에서 더 자연스럽다. |
| 카카오맵 | 해외 지도를 제공하지 않는다. |
| Google Maps JS로 렌더링 | 사용량에 따라 비용이 늘고, 지도 스타일을 디자인 시스템에 맞추기 어렵다. |
| Pragmatic drag and drop | 최근 메이저 버전이 기능이 아닌 진입점 재배치였고, 사용량이 dnd-kit의 약 1/17이다. |
| `@dnd-kit/react` | 아직 0.x라 API가 바뀔 수 있다. |

## 결과

- 좋은 점: 타일 비용이 저장소와 전송량뿐이다(R2는 전송료 무료). 한국어 라벨이 나온다.
- 감수할 점: PMTiles 추출과 갱신 스크립트를 관리해야 한다. 기존 Leaflet 렌더링 코드는 다시 써야 한다. 경로 계산 함수는 그대로 쓴다.

## 다시 볼 조건

- `@dnd-kit/react`가 1.0이 되면 옮긴다.
- 일본 대중교통 소요 시간이 필요해지면 Ekispert나 NAVITIME 요금을 확인한다.

## 확인 필요

- OpenFreeMap 스타일이 `name:ko`를 지원하는지 확인하고, 없으면 처음부터 Protomaps로 시작한다.
- 네이버 지도의 해외 표시 정책을 NCP 문서에서 확인한다.
