# 0005. BFF 세션 인증과 Valkey

- 상태: 제안
- 날짜: 2026-10-16

## 맥락

로그인은 구글 로그인과 이메일 가입이다(로그인 수단 구조는 ADR 0009). 브라우저 자바스크립트가 토큰을 읽을 수 있으면 XSS 한 번에 계정이 넘어간다. 로그아웃이나 탈퇴, 공유 권한 회수는 즉시 반영되어야 한다. 2025년 2월 개인정보위의 소셜 로그인 점검은 탈퇴 시 토큰 revoke를 하지 않는 서비스를 지적했다.

## 결정

- Next.js가 같은 출처(same-origin) 프록시 역할을 하고, 브라우저에는 `__Host-` 접두어의 httpOnly, Secure, SameSite=Lax 쿠키로 불투명한 세션 ID만 준다.
- 세션은 Spring Session이 Valkey 9.1에 JSON으로 저장한다. 로그아웃과 강제 만료는 세션 삭제로 즉시 반영된다.
- CSRF는 Spring Security 7의 `csrf.spa()`로 처리한다.
- 탈퇴는 세 단계로 한다. 계정과 여행 삭제, 구글 토큰 revoke, 업로드 이미지 삭제. 뒤의 두 단계는 Modulith 이벤트로 처리해 실패해도 다시 시도된다.
- 같은 Valkey 인스턴스를 날씨 응답 캐시와 쓰기 API 레이트리밋 버킷에도 쓴다.

## 고려한 대안

| 대안 | 기각 이유 |
| --- | --- |
| 쿠키에 JWT | 만료 전 강제 무효화를 하려면 결국 서버 저장소가 필요하다. 토큰 크기도 크다. |
| localStorage에 토큰 | XSS에 그대로 노출된다. |
| Redis 8 | 2025-05부터 AGPLv3가 추가됐다. Valkey는 BSD-3이고 Spring Data Valkey가 GA다. 기능 차이는 이 규모에서 없다. |
| 캐시를 Caffeine으로만 | API 인스턴스가 하나일 때는 충분하지만 세션 저장소가 따로 필요하다. 세션 때문에 Valkey를 두는 김에 캐시도 함께 둔다. |

## 결과

- 좋은 점: 브라우저 코드가 토큰을 전혀 다루지 않는다. 권한 회수가 즉시 반영된다.
- 감수할 점: Valkey가 내려가면 로그인 상태가 끊긴다. Valkey는 같은 호스트에서 AOF를 켜서 재시작 시 세션을 복구한다.

## 확인 필요

- Spring Data Redis 4.x의 Jackson 3용 JSON 직렬화 클래스 이름을 레퍼런스 문서에서 확인한다.
- `__Host-` 접두어와 `server.servlet.session.cookie.*` 설정 조합을 통합 테스트로 확인한다.
