# Mobile UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optimize the existing family itinerary for 390–430 px mobile screens while preserving all content, interactions, and desktop behavior.

**Architecture:** Keep the existing render functions and breakpoint-based CSS architecture. Add small semantic wrappers and accessible button labels where mobile and desktop need different presentations, then replace the current narrow three-column mobile timeline and modal overrides with dedicated phone layouts. Verify static behavior with Vitest and real layout behavior in the browser.

**Tech Stack:** Vite, vanilla JavaScript, CSS, Vitest, jsdom, Leaflet

**Spec:** `docs/superpowers/plans/2026-09-21-mobile-ui-design.md`

## Global Constraints

- Do not change itinerary, restaurant, flight, or airport-guide content.
- Preserve desktop layout above 780 px.
- Support 390 px and 430 px phone widths without horizontal page overflow.
- Keep every primary mobile action at least 44 px high.
- Preserve reduced-motion behavior and all existing keyboard-accessible labels.
